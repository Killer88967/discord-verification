# Security Policy

Security is a core part of Discord Verification Bot.

Please do not publicly disclose vulnerabilities that could compromise
verification sessions, Discord accounts, server configurations, user
privacy, authentication, authorization, or stored security data.

## Reporting a vulnerability

Please report security vulnerabilities privately through GitHub's
Private Vulnerability Reporting feature when available.

Do not open a public GitHub Issue for an exploitable vulnerability.

A useful report should include:

- A description of the vulnerability.
- The affected component.
- Steps required to reproduce it.
- The potential security impact.
- Any proof-of-concept code or requests, when appropriate.
- Suggested mitigations, if known.

## Sensitive areas

Examples include:

- Verification bypasses.
- Session-token vulnerabilities.
- Authentication or authorization bypasses.
- Discord role-assignment vulnerabilities.
- Account-linking or alt-detection information leaks.
- Cross-guild information disclosure.
- Database exposure.
- Secret or credential exposure.
- Request forgery.
- Injection vulnerabilities.
- Abuse of internal APIs.
- Fingerprinting or privacy vulnerabilities.

## Responsible disclosure

Please allow maintainers reasonable time to investigate and fix a
reported vulnerability before publicly discussing it.

Do not intentionally access, modify, destroy, or disclose data belonging
to other users while testing a vulnerability.

## Supported versions

Discord Verification Bot is currently under active development.

Until stable releases are published, only the latest version of the
default branch is actively supported.
